# blog-asset-pipeline

記事を読んで、必要な画像を正確に割り出し、欠けのある一式や不正な一式を納品させないためのコマンドラインツールです。

自動化しているのは**抽出・計画・検証・梱包**です。画像の生成はしません。そこは人が画像ツールを操作する工程のままで、このツールの役割は、戻ってきたものが揃っていて、寸法が正しく、命名が正しく、説明が付いていることを確かめることです。

```
blog-assets plan  article.html --out delivery/   # 必要な画像を割り出す
#            ... 画像を作る ...
blog-assets check delivery/                      # 納品できる状態か
blog-assets check-archive delivery/ delivery.zip # 書庫は綺麗か
```

技術文書の本体は英語の [README.md](README.md) です。この文書は要点だけをまとめたものですので、詳細はリンク先をご覧ください。

## 何を解決するのか

記事向けの画像一式を、継続的な有償の仕事として作っています。記事1本につき、ヘッダー画像が1枚、本文の見出しごとに1枚、SNS用の正方形が1枚必要です。画像ごとに寸法が決まっていて、位置の番号を含むファイル名と代替テキスト（alt）が付き、zipで納品します。

手作業でやると、**クライアントがファイルを開くまで見えない形で**失敗します。

| 失敗 | なぜ見えないのか | どう捕まえるか |
|---|---|---|
| 見出しの取りこぼし | 保存したページに本文とナビゲーション・目次・共通のフッタが混ざる | 除外した見出しを理由つきで全件報告する |
| 投稿の拒否 | CMSがファイル名の長さを**バイト**で数える | 文字を分割せずにバイト上限で切り詰める |
| ファイルの消失 | macOSは分解形（NFD）で保存し、台帳は合成形（NFC）で持つ | 比較の前に両方を正規化する |
| 寸法の誤り | 切り抜いた後に測り直さない | ファイルのヘッダから寸法を読んで計画と突き合わせる |
| 下書きの混入 | 同じフォルダに置いてある | 台帳にない画像は失敗として扱う |
| altの書き忘れ | 別ファイルにある | 納品する全ファイルがaltのファイルに現れることを要求する |
| zipへのごみの混入 | 作業用の下位フォルダや隠しファイルが巻き込まれる | 書庫の項目をフォルダと1件ずつ突き合わせる |

台帳が要になります。JSONではなくMarkdownにしているのは、画像を作る人が作業中に進捗の列を手で編集するためで、テキストエディタで開いて壊れない形である必要があります。解析側は見出し行から表を見つけ、列を**名前で**対応づけますので、列を足してもファイル名の位置がずれることはありません。

## 動かし方

Python 3.9以降で、実行時の依存はありません。

```bash
pip install -e .
blog-assets plan tests/fixtures/sample_article.html --out delivery/
blog-assets check delivery/
blog-assets check-archive delivery/ delivery.zip
```

`check` は納品できない場合に終了コード `1` を返します。すでに `ledger.md` があるフォルダで `plan` を再実行すると `ledger.new.md` に書き出しますので、記録した進捗が消えることはありません。`--force` を付けると上書きします。

寸法と命名の上限はプロファイルにまとめてあります。要件の異なるクライアントが増えても、必要なのはJSONファイル1つであってコードの変更ではありません（[Delivery profiles](README.md#delivery-profiles)）。

## 主な判断

- **画像のヘッダを自分で読み、外部コマンドを呼ばない** — 元の実装はmacOS専用の `sips` で寸法を測っていました。PNG・JPEG・GIF・WebPの4形式を先頭30バイト前後から直接読む形に変えたので（JPEGはフレームヘッダの位置が固定でないためセグメント表をたどります）、LinuxでもWindowsでも、CIでも同じ検査が動きます
- **除外は必ず報告し、黙って落とさない** — ナビゲーション・目次・フッタ・要約の後の共通ブロックから見出しを除きますが、除いたものは理由つきで並べます。除いた数が残した数を上回った場合は、想定外の形で保存された可能性を警告します。**黙って消えた見出しだけが、クライアントに届いてしまう失敗です**
- **壊れた記法から復帰する** — 閉じていない `<h2>` が次の見出しを飲み込んでいました。ブロック要素か次の見出しが始まった時点で閉じ、印を付けて残します
- **文字数ではなくバイト数で数える** — ファイル名の上限はUTF-8のバイト数で、文字を分割せずに切り詰めます。`NN_` の接頭辞、拡張子、正方形画像が足す `_sq` も上限の計算に入れます
- **比較の前に正規化する** — ファイル名はNFCで比較します。macOSはNFDで書き、エディタはNFCで書くためです
- **検査器はlintではなく差分** — 台帳とフォルダとaltのファイルを互いに突き合わせます。3つが一致して初めて納品できます

採用しなかった案とその理由は [Alternatives considered](README.md#alternatives-considered) にあります。作業用のチェックリストをJSONにする案、寸法の取得に画像ライブラリを使う案、見出しをASCIIに変換する案、最初の問題で止める案です。

## クライアント情報の扱い

このリポジトリに**クライアントの資料は一切ありません**。自動化している業務は実在しますが、クライアント、その記事、画像、寸法、指示文、納品履歴はここにはなく、これまでもありませんでした。一般化した問題から作り直したもので、Git履歴も新規です。

`tests/fixtures/` の中身はこのリポジトリのために作ったものです。テストで使う画像はテスト実行時に1バイトずつ生成しますので（`tests/conftest.py`）、バイナリは1つもコミットしていません。

## テスト

```bash
pytest          # 69件
ruff check .
ruff format --check .
```

CIは Linux・macOS・Windows で Python 3.9 と 3.13 に対して、コマンドラインの疎通確認も含めて実行します。納品の検査のテストは、**通る一式をまず作り、テストごとに規則を1つだけ壊す**方法で書いています。ファイルの欠落、寸法の誤り、空ファイル、余分な画像、埋まっていない進捗の列、altの欠落、ディスク上の分解形のファイル名です。

## 制約

- **altの有無は見ますが、質は見ません。**納品する各ファイルにaltの記載があることは確認できますが、その文章が役に立つかどうかは判断できません
- **見出しの検出は経験則です。**CMSから保存したページに合わせてあります。独特な記法の手書きページでは、台帳に手で見出しを足す必要が出ます。除外を印刷しているのはそのためです
- **要約の検出は英語だけです。**要約より後の共通ブロックを落とす規則は英語の見出しに一致します。他の言語では対応を広げる必要があります
- **対応する画像形式は4つです。**PNG・JPEG・GIF・WebPで、AVIFとHEICは推測せずに未対応として報告します
- **画像の生成も寸法変更もしません。**意図的に範囲外です。このツールは仕事を検査するもので、仕事そのものはしません
